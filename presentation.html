Privamon Pipeline
A 10-step on-device visual redaction pipeline that protects your privacy before AI agents see your screen. Zero PII leaves your browser.
🖥️ On-Device ⚡ Real-Time 🧠 AI-Powered
Press → or click › to begin  ▶
01 On-Device
📸
Capture
Screen + DOM Map
Captures a pixel-perfect screenshot of the active tab using chrome.tabs.captureVisibleTab and simultaneously walks the DOM tree to extract element metadata, bounding boxes, and semantic labels.
chrome.tabs API DOM TreeWalker MV3 Service Worker
capture.js
02 On-Device
📦
Sandbox
Offscreen Document
All heavy ML inference runs inside a Chrome Offscreen Document — an invisible headless page that has full Canvas and WASM access without blocking the user's active tab at 60 FPS.
Offscreen API Canvas 2D WASM SIMD WebGPU
offscreen-sandbox.js
03 On-Device
🔍
Detect
OCR + Face Model
Runs Tesseract.js (English + Hindi OCR) and UltraFace ONNX face detection in parallel. Tesseract extracts all visible text; UltraFace locates human faces with bounding boxes.
Tesseract.js UltraFace ONNX ONNX Runtime Web eng + hin
detect-engine.js
04 On-Device
📝
Text
Text, Checksums, NER
Applies regex patterns, mathematical checksums (Verhoeff for Aadhaar, Luhn for credit cards), and a quantized bert-base-NER model to classify every text fragment as PII or safe.
Verhoeff Algorithm Luhn Checksum bert-base-NER Regex Heuristics
pii-detector.js
05 On-Device
🔗
Fuse
UI Rules + 3rd Decision
A spatial grid IoU merge combines overlapping detections from DOM, OCR, vision, and NER. Each candidate is scored across tiers: REDACT / REVIEW / KEEP, with thresholds tuned from user-correction feedback.
Spatial Grid IoU Merge REDACT / REVIEW / KEEP
fusion-engine.js
06 On-Device
⬛
Redact
Solid Black Fill
Renders opaque #000000 rectangles directly onto a fresh Canvas 2D surface over every confirmed detection bounding box. No reversible blurs or translucent masks — solid pixel overwrite only.
Canvas 2D fillRect #000000 Opaque Pixel Overwrite
canvas-redactor.js
07 On-Device
🧹
Sanitize
REDACTED Tokens
Walks the extracted DOM tree and replaces every detected PII value with a safe placeholder token like [REDACTED]. This tokenized DOM is what gets sent to the server — never the raw text.
DOM Tokenization [REDACTED] Tokens dom-tok-N IDs
sanitize-dom.js
08 On-Device
✅
Audit
Pixel Audit, Eye-Ready
Runs a post-redaction pixel-level verification pass. For each bounding box, it checks that pixels are truly #000000. If any leak is found, it expands the box by 25% and re-redacts in a retry loop.
Pixel Inspection 25% Expansion Retry Opacity Audit
audit-verifier.js

Server
Redacted view only
Crossing the Trust Boundary
Only the redacted screenshot and sanitized DOM tokens leave the browser. The server never sees raw PII — only safe, blacked-out representations.
🔒 Zero raw PII transmitted 📸 Redacted image only
09 Server
🧠
Interpret
Redacted View → Action Plan
A Vision-Language Model (Qwen3-VL-8B-Instruct) interprets the redacted screenshot + sanitized DOM to understand the page and plan the next user action. It only ever sees blacked-out data — pluggable to swap in stronger models.
Qwen3-VL-8B OpenRouter API Pluggable VLM
vlm-interpret.js
10 Server
⚙️
Plan
Return Action + Element Token
The VLM returns a structured action (click, type, scroll) with a DOM element token. The browser validates the token locally, executes the action, then re-captures — completing the privacy-safe agentic loop.
Action Executor Token Validation Agentic Loop
action-planner.js
